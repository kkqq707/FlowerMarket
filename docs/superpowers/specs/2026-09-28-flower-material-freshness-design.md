# 花材批次、保鲜与配送联动设计

## 目标与既有能力

为花间集增加可执行的花材批次库存管理：店员能登记入库与到期，花束按配方占用花材，订单不会预约到到期或不足的花材。保留现有商品 SKU 库存、订单下单扣库存、配送区域、预约时段容量、截单时间、履约进度和准时送达率，不建设第二套通用商城。

此模块与“花卉养护知识”独立实现，但可向商品详情提供建议观赏期。现有 12 款演示花礼补齐配方和批次数据；其他历史花卉商品保持原流程，直到店员完成配置并主动启用批次管理。

## 数据模型与不变量

- **花材**：名称、计量单位（如枝/把）、默认仓储保鲜天数、建议观赏天数、低库存阈值、启用状态。花材是原料，不等同于可售商品 SKU。
- **批次**：花材 ID、批次号、入库日、到期日、入库数量、现存数量、已锁定数量、备注与操作时间。`可分配 = 现存 - 已锁定`，所有数量非负；到期日早于预约交付日的批次不可分配；到期日当天可分配到该日。
- **花束配方**：可售商品 ID、花材 ID、每件用量。商品扩展资料新增“启用批次管理”标志；启用前必须有完整且用量大于零的配方。启用后即使缺批次也要报缺货，不能静默退回旧库存路径。
- **订单分配记录**：订单号、花材 ID、批次 ID、锁定数量、`RESERVED / CONSUMED / RELEASED` 状态与时间。对同一订单和批次的操作幂等，记录锁定时实际使用的批次与数量，日后修改配方不影响既有订单。
- 已启用批次管理的商品同时受原 SKU 库存与花材可分配量约束。原 SKU 库存由现有商城逻辑负责，花材服务不得再扣一次 SKU 库存。

## 库存与订单流程

1. 店员维护花材及花束配方，登记批次入库。默认到期日可根据仓储保鲜天数带出，但必须允许按实际到货情况修改；已锁定数量不能被盘点调整为负数。
2. 顾客选择配送时段或到店取花日期；过去的取花日期不得提交。下单在现有数据库事务中，根据订单商品行计算所需花材，对交付日仍合格的批次按到期日、入库时间排序分配（先到期先用）；必要时可拆分多个批次。使用行锁或条件更新保证并发下不会超卖，花材不足时整个下单事务回滚并提示具体花材不足，不自动替换。
3. 待支付订单保留锁定。用户在制作前取消、支付预约超时、或订单创建事务失败时释放锁定；重复释放不改变数量。支付成功不重复锁定。
4. 订单首次进入 `PRODUCING` 时把锁定量转为实际消耗，同时减少批次现存和已锁定数量；重复阶段回调不得再次消耗。开始制作后的取消或售后不自动将已使用花材加回库存，需由店员按实物盘点调整。
5. 配送仍使用已有区域、起送金额、时段容量与截单规则。结算页显示可预约时段与剩余容量，并在提交时重新校验；所选交付日同时用于批次到期校验。订单详情继续显示承诺时段与配送进度，不承诺未接入的实时骑手 ETA。

## 管理端与小程序

- 管理端在“花店经营”新增“花材库存”入口：花材列表及低库存预警、批次入库与盘点、临期/过期筛选、花束配方维护。库存卡片明确区分现存、已锁定、可分配；临期阈值固定为未来两天，过期批次不可手动启用销售。花卉商品编辑页显示批次管理开关与配方状态，未配置商品标记“待配置”。
- 商品详情页可展示由配方花材推导的“建议观赏期”（取已启用花材的最短参考天数；资料不全则不显示数字），并保留现有养护说明与配送说明。商品页展示的普通库存数字不能被误称为交付日可用花材；结算提交结果以服务端复核为准。
- 管理端配送设置保留已有区域与时段表，不复制一份时效配置。经营看板可增设临期和低库存待办入口，但不改变既有准时送达率口径。

## 兼容、迁移与验收

- 新增单独的幂等 SQL 升级脚本；先备份相关表，再建表与索引，再导入 12 款演示花礼的明确配方和演示批次。不得删除历史订单、商品或库存。迁移前后的旧商品默认 `batchManaged=false`，仍按原 SKU 库存下单；管理端提示配置缺口。
- 批次到期按门店业务时区的日历日期判断，服务端负责所有数量与日期校验，不信任前端展示。对同一花材的并发下单、跨批次分配、当日到期、次日到期、取消/超时重复释放、重复制作回调、已消耗售后、配置开关与历史兼容分别测试。
- 验收包括 Java 单元与集成测试、SQL 迁移检查、管理端构建、小程序构建，以及管理端入库/预警和小程序结算/错误提示的实际页面检查。若无法连接本地数据库或微信开发者工具，应明确报告未实测部分，不能以构建通过代替端到端验证。
