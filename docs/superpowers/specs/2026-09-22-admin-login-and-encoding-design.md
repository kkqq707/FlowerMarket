# 花间集管理后台登录页与编码修复设计

## 目标

修复管理后台动态菜单乱码，降低登录页首屏负担，并将登录页重设计为适合花店店主与店员高频使用的花艺品牌工作台。同时移除管理后台所有用户可见的版权/公司名称页脚。

## 已确认方向

用户选择了第 2 套构图：暖白画布中的横向花艺工作台。主面板由花材图片区、品牌区和登录表单区组成。用户明确要求移除截图中圈出的版权信息，并且后台所有页面均不再出现该类信息。

## 视觉系统

- 主色：墨绿 `#1f5a3c`
- 背景：暖白 `#f5f1e8`
- 辅色：鼠尾草绿 `#8ea58f`、柔和玫瑰粉 `#d98995`
- 文字：深墨色 `#203129`，次级文字 `#66736b`
- 组件：12–16px 圆角、单一柔和阴影、清晰焦点环，不使用玻璃拟态或渐变
- 字体：后台操作界面使用可靠的中文无衬线系统字体

## 页面结构

桌面端中央放置三段式横向主面板：左侧约 30% 显示本地花材图片和品牌短句，中间约 31% 显示花间集文字标识与欢迎语，右侧约 39% 放置登录表单。窄屏隐藏装饰图片区，品牌与表单纵向排列。

## 性能策略

- 移除 `canvas-nest` 粒子动画和 Swiper 轮播依赖的登录页导入。
- 登录首屏不再请求远程背景图和轮播图。
- 使用已有、约 196KB 的本地花材图片，不复用 1.6MB 构图稿或 619KB 文字 Logo 作为首屏主视觉。
- 站点域名与 Logo 配置延后到登录成功后并行获取，不阻塞登录页渲染。

## 乱码修复

数据库存储是正确 UTF-8；乱码由 `ResponseFilter` 使用无字符集参数的 `String#getBytes()`，在中文 Windows 上按 GBK 输出 JSON 导致。修复为显式 UTF-8 输出，并在响应头中声明 `application/json;charset=UTF-8`。

## 全局页脚

登录页不渲染底部公司名称；后台主布局不再挂载版权页脚组件。业务弹窗中的“footer”操作区不受影响。

## 验收

- `/api/admin/getMenus` 原始字节可按 UTF-8 正确解码为“运营、商品、订单”等。
- 登录页桌面与移动端无横向溢出，表单可键盘操作，登录流程与验证码逻辑保持。
- 页面无粒子画布、无轮播、无用户可见版权/公司名称。
- 前端生产构建与后端回归测试通过。
